# النسخة المركزية v6 — دليل التشغيل

> **تنبيه:** الحزمة المدمجة تضيف Product Studio وExport Center إلى النسخة السحابية، وتدعم حفظ ملفات PDF المصدّرة في Google Drive. هذه الإضافات لم تُختبر على Google Drive أو PostgreSQL أو Cloud Run حقيقي؛ يلزم تثبيت المتطلبات وتشغيل الاختبارات ومراجعة `REPORT_AR.md` قبل الاعتماد.

## وظائف إدارة المنتجات والتصدير المضافة
- من `/studio/`: إدارة المنتجات والموديلات، مواصفات مشتركة وخاصة بالموديل مع سجل للتعديلات، ومعرض صور المنتج والموديل.
- من `/export-center/`: إنشاء TDS وكتالوج منتج وكتالوج شامل، ضبط القوالب والهوية، معاينة PDF، وحفظ سجل إصدارات قابل للتنزيل.
- الصور والكتالوجات الأصلية وملفات PDF المصدّرة تحفظ في Drive عند `STORAGE_BACKEND=drive`؛ قاعدة البيانات تحتفظ بمعرّف Drive، والملفات المؤقتة داخل Cloud Run ليست مخزنًا دائمًا.
- ترحيل البيانات يتضمن جداول الصور المرتبطة بالمنتجات، وسجل إصدارات الهوية، وسجل التصدير. احتفظ بنسخة البيانات القديمة وتحقق من تقرير الترحيل قبل تحويل المستخدمين.
- عند استخدام الوضع المحلي، ملفات PDF المصدّرة تحفظ تحت `data/exports`.

## أدوات Enterprise Pro في v5
- افتح `/pro/` للمحول ومقارنة الموديلات المعتمدة، ومصفوفة مواصفات العائلة، وحزمة الاعتماد الفنية.
- حزم الاعتماد تقبل ملفات PDF فقط، حتى 10 ملفات (8 ميجابايت لكل ملف و24 ميجابايت إجمالًا)، وتضم خطاب تقديم وTDS للموديلات المعتمدة والمرفقات المرفوعة.
- أدوات PDF تحفظ ملفاتها في وسيط التخزين وسجل التصدير، مع عدد الصفحات وخيارات الإنشاء.
- بوابة العميل مغلقة افتراضيًا. مالك النظام وحده يستطيع نشر موديل معتمد ونشط وظاهر؛ إخفاءه أو إلغاء اعتماده أو تعطيله يسحب النشر. الصور العامة تقتصر على الصور المعتمدة للكتالوج.
- قبل النشر على الإنترنت، اضبط `PUBLIC_BASE_URL` على عنوان HTTPS النهائي. تظهر روابط QR فقط للموديلات المنشورة، وتُنشأ برموز QR حقيقية.
- عند بدء التشغيل تُضاف خانة `public_enabled` إلى قاعدة بيانات قديمة تلقائيًا، وتكون قيمتها الافتراضية صفرًا؛ لذلك لن يُنشر أي موديل قديم تلقائيًا.

## مراجعة الواجهة في v6
- أُعيدت صياغة النصوص الظاهرة في الشاشات ورسائل النظام والإشعارات بالعربية الفصحى، ووُحّد مصطلح `model` في الواجهة إلى «الطراز».
- جرى الحفاظ على أسماء الخدمات والتنسيقات والاختصارات الفنية مثل Google Drive وPDF وTDS كما هي.

## إصلاحات الإصدار v4
- تم توحيد PDF تحت `pdf_engine.py`؛ `pdfgen.py` يحتفظ بواجهة توافق فقط.
- الصورة المعتمدة تُختار حسب نوع المستند. تعذّر تنزيل ملف صورة من Drive لا يوقف PDF، وتظهر رسالة `No approved image for this document.` عند عدم وجود صورة صالحة.
- استعادة فواصل المنتجات تعالج نقص الصفحات في الكتالوج الشامل، وعدد الصفحات الفعلي يُحفظ في سجل التصدير.
- ترتيب العربية الطويلة يُعالج على مستوى كل سطر. راجع PDF على بيانات الشركة بعد تثبيت `arabic-reshaper` و`python-bidi`، إذ لم تتوفر المكتبتان في بيئة الفحص السابقة.
- ربط الصور يتحقق من المراجع قبل الحفظ، ورسالة الخطأ تشرح السجلات المحذوفة بدل إرجاع خطأ 500.

## الملفات الجديدة
المسارات القديمة من البحث والشجرة ومعاينة الهوية تستخدم محرك PDF نفسه، وتحفظ ملفاتها في Drive وسجل التصدير. صفحة `/studio/unlinked-images` تتيح مراجعة الصور غير المرتبطة وربطها بمنتج أو موديل أو تعطيلها. سجل الهوية يسمح باستعادة إعداد سابق كإصدار جديد، وسجل التصدير يسمح بفتح إعدادات إصدار سابق لإعادة استخدامها.

لفحص التصدير محليًا، شغّل `python tests/run_acceptance.py`. ينشئ الفحص قاعدة SQLite مؤقتة وبيانات اختبار منفصلة، ثم يصدر أربعة ملفات PDF، وخامسًا بالعربية إذا توفرت مكتبتا تشكيل العربية، ويرسم الصفحات إلى PNG داخل `tests/acceptance_output/`. يمكن اختيار مجلد مختلف عبر `--output-dir PATH`. لا يكتب الفحص إلى قاعدة بيانات الإنتاج ولا يتصل بـ Google Drive.

إعدادات الخط والشفافية والزوايا والنزف تتحقق خادميًا عند حفظ الهوية؛ القيم خارج المجال تُرفض برسالة واضحة.

`db.py` (طبقة قاعدة البيانات: PostgreSQL/SQLite + ترقيات الإصدارات) · `auth.py` (الدخول والمستخدمين) · `catalogs.py` + `dedupe.py` (رفع الكتالوجات وكشف التكرار) · `storage.py` + `gauth.py` + `assets.py` (Drive والأصول) · `dataio.py` + `admin.py` + `integrity.py` (نسخ احتياطي واستعادة وفحص) · `migrate_to_cloud.py` (ترحيل البيانات القديمة) · `manage.py` (أوامر إدارة) · `scripts/` · `Dockerfile` + `deploy.sh` · `tests/`.

## 1) تجهيز جوجل (مرة واحدة)
1. في Google Cloud أنشئ مشروعًا وفعّل Drive API وSheets API.
2. OAuth consent screen: خلّي الحالة **In production** (في Testing الـ refresh token بيموت بعد 7 أيام).
3. أنشئ OAuth client من نوع Desktop، نزّل `credentials.json` جنب `app.py`، وشغّل على جهازك: `python scripts/get_token.py > token.json` وسجّل الدخول بحساب جوجل **اللي هيمتلك الملفات**. التطبيق بينشئ مجلد «Catalog System» بنفسه (صلاحية `drive.file`).

## 2) النشر
راجع `deploy.sh` ونفّذ خطواته واحدة واحدة (Cloud SQL + نسخ تلقائي يومي واستعادة لأي لحظة، الأسرار، Cloud Run). الـ HTTPS بيجي تلقائيًا مع Cloud Run.
- أول مستخدم (المالك) بيتعمل من `OWNER_USERNAME/OWNER_PASSWORD`. باقي الموظفين من صفحة «المستخدمين».
- **حد الرفع:** Cloud Run بيحدد 32 ميجا للطلب الواحد على HTTP/1. الكتالوج الأكبر: اضغط الـ PDF أو قسّمه. (رفع أكبر محتاج HTTP/2 end-to-end أو رفع مباشر لـ Drive، ومش متنفّذ.)

## 3) ترحيل بياناتك الحالية
على الجهاز اللي عليه النظام القديم (بعد إيقافه):
```
cp -r data data_backup_before_migration          # نسخة احتياطية أولًا
python migrate_to_cloud.py --source-dir data --dest "$DATABASE_URL" --dry-run     # فحص بدون كتابة
STORAGE_BACKEND=drive GOOGLE_OAUTH_TOKEN_JSON="$(cat token.json)" \
python migrate_to_cloud.py --source-dir data --dest "$DATABASE_URL" [--reuse-drive-ids]
```
بيحافظ على كل المعرّفات، ويكتب `migration_report.json` (مراجع يتيمة، ملفات ناقصة، نتيجة التحقق). لو الرسالة النهائية مش `MIGRATION OK` ما تحوّلش الموظفين. لو الرفع وقف في النص: أعد التشغيل بـ `--files-only`.

## 4) النسخ الاحتياطي والاستعادة
- تلقائي: Cloud SQL (يومي + PITR). إضافي: `scripts/pg_backup.sh`.
- من التطبيق (المالك): «نسخ احتياطي» ← ZIP بكل الجداول والمعرّفات.
- **اختبر الاستعادة بدون المساس بالإنتاج:** `python scripts/restore_drill.py backup.zip`.
- استعادة فعلية: `python manage.py restore backup.zip --yes` (بتستبدل المحتوى كله).
- الكتالوج المحذوف بالغلط: صفحة «المحذوفات» ← استعادة.

## 5) اختبار على كتالوجاتك الحقيقية
`python scripts/catalog_lab.py مجلد_الـPDFs` (مع `meta.csv` اختياري: name,supplier,version,date) بيشغّل الاستخراج وكشف التكرار على قاعدة مؤقتة ويطبع القرار لكل ملف. شغّله على كتالوجات حقيقية بأسماء وإصدارات مختلفة وابعتلي النتيجة.

## 6) تشغيل الاختبارات
`python -m unittest discover -s tests` (56 اختبار). على PostgreSQL: `TEST_DATABASE_URL=postgresql://... python -m unittest discover -s tests` (لسه ما اتشغّلتش).

## التشغيل المحلي القديم
`run.bat` بيشتغل كما كان (بدون دخول، ملفات محلية) — للتجربة فقط، مش للاستخدام المشترك.
